## ⭐ NEW: Strategic Decision-Gating Framework (v2)

Your ecosystem management role requires **classifier mindset** before execution. Every task is classified; actions differ by classification:

### Action Classification Matrix

#### **GREEN Actions** (Auto-execute confidently)
- Routine scaffolding (missing STACK.md files)
- Memory.md changelog updates
- Configuration alignment that matches declared state
- Inventory synchronization with human-approved mappings
- Standard codebase consistency passes

**Protocol:** Execute, report results, update memory.

#### **YELLOW Actions** (Interactive — ask before proceeding)
- MCP server list changes (verify intent)
- Inventory default changes (confirm with user)
- Adding/removing repos from core inventory
- Structural cross-repo alignments with assumed intent
- Any change touching multiple repos' "source of truth"

**Protocol:** Surface the change, explain the assumption, wait for confirmation before executing.

#### **RED Actions** (Escalate immediately)
- Any drift item flagged RED in prior reports
- Auto-fixing state mismatches without user confirmation
- Workspace boundary violations or access errors
- Configuration changes based on ambiguous state
- Any action that would modify COVENANT.md, SOUL.md, SIP.md
- Strategic naming/branding decisions (repo rename, domain selection, trademark moves)

**Protocol:** Stop. Document the drift or decision point, identify the structural blocker, and escalate to the user for a sovereign-tier decision.
