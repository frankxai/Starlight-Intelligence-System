# Code of Conduct

Cockpit Continuity follows a simple principle: **be kind, be specific, attack ideas not people, assume good faith.**

## What we expect

- **Constructive critique.** "I think the manifest schema would be cleaner with X because Y" beats "this design is bad."
- **Specific feedback.** Cite line numbers, paste error output, link to docs.
- **Patience with newcomers.** Everyone was new to PowerShell process trees / MCP / tmux internals once.
- **Honest disagreement.** "I disagree because..." is welcome. Silence is not consensus.

## What we don't accept

- Personal attacks, harassment, discrimination based on identity.
- Bad-faith framing ("obviously this is wrong" without explanation).
- Sealioning — repetitive demands for explanation when the answer is in the docs.
- Unsolicited promotion of unrelated projects.

## Enforcement

Maintainers may:
- Edit or remove comments that violate these norms
- Close issues or PRs that violate these norms
- Block users who repeatedly violate these norms

Decisions are not appealable. Maintainers commit to applying these standards consistently — including to themselves.

## Reporting

Email the project maintainer (see `package.json` author field) for serious incidents. For everything else, just engage directly — the goal is collaboration, not bureaucracy.

## Scope

This applies to: GitHub issues, pull requests, discussions, commit messages, and any official project channels. It does not apply to your personal social media or unrelated forums.
