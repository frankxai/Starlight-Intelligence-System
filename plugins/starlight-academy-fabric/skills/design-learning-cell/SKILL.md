# Design Learning Cell

## Outcome

Produce a community experience that improves learning quality, distributes stewardship, and creates reusable public value without requiring constant founder presence.

## Design laws

- Community is a learning interface, not a chat feed or access perk.
- Use the smallest cell that can sustain perspective diversity, peer help, and visible contribution.
- Reserve human review for judgment that cannot be responsibly automated; prefer group studios and bounded review windows over standing one-to-one access.
- Protect private learner work, allow observation before participation, and make exit and export easy.

## Method

1. Name the shared purpose, target artifact, duration, participation modes, and conditions for a useful session.
2. Define roles such as learner, peer reviewer, steward, domain reviewer, accessibility contact, and moderator. Keep assessment and credential authority named and separate.
3. Design the rhythm: orientation, build room, critique, revision, showcase, reflection, and optional steward handoff.
4. Specify contribution loops so notes, templates, examples, and fixes can return to the Commons with consent and appropriate licensing.
5. Set moderation, care, conflict, appeal, privacy, deletion, accessibility, and non-participation paths.
6. Define health signals: active learners, completed artifacts, peer-help ratio, contribution distribution, steward load, retention, safety findings, and accessibility blockers.
7. Add managed capacity only for scarce facilitation, hosting, compute, or service guarantees. Never sell social proximity as a stronger credential.

## Output

Return a cell charter, member promise, roles, cadence, artifact flow, review boundary, contribution loop, safety and accessibility rules, capacity model, health signals, and shutdown or renewal decision.
