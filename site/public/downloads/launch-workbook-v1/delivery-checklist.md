# Delivery acceptance checklist

Product/version: [ ] · Reviewer/date: [ ] · Evidence folder: [ ]
Each result is pass, fail or untested. Untested is not a pass.

## Content

- [ ] Every promised file exists and opens in its stated format.
- [ ] A complete example demonstrates the first task without invented outcomes.
- [ ] Links point to intended public pages; restricted links are labeled.
- [ ] Original work and third-party license/attribution notices are distinguishable.
- [ ] Secrets, personal data, private account IDs and customer records are absent.

## First use

- [ ] A new user can identify prerequisites and separate tool costs.
- [ ] Download and extraction work in a clean directory.
- [ ] The documented first task produces the specified output.
- [ ] Failure instructions explain what to check and how to recover.
- [ ] Website keyboard navigation, focus, contrast and narrow-screen layout work.

## If selling on your own website

- [ ] Price, currency, tax treatment, scope and delivery terms are clear.
- [ ] Checkout success, cancellation and failure were tested in provider test mode.
- [ ] A verified webhook delivers once; retries cannot create duplicate entitlements.
- [ ] Receipt and download are tied to the correct customer and product version.
- [ ] Refund, cancellation and support paths match your actual service and terms.
- [ ] No live payment or account migration happens without its owner's authorization.
