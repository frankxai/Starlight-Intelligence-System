# Worked example: a project handoff pack

Fictional demonstration. This is not a customer story, a sales result or a
claim about any released Starlight product. All amounts below are illustrative.

## Buyer and trigger

A solo developer is handing a small website to a collaborator. The collaborator
cannot reproduce the build from chat history. The workaround is a call plus a
collection of messages; the recurring job is to produce a clear handoff.
Demand evidence is missing. The next research step is to watch a real recipient
try to start one authorized project using its existing instructions.

## Offer

A plain-text template pack helps the developer produce a README, environment
variable names without values, verification commands, a known-issues list and
a recovery note. Completion means the recipient can follow the supplied steps
and record which checks pass. It does not guarantee the project will run.

Included: five editable Markdown templates and one fictional filled example.
Required: access to the project, a working local build and rights to share it.
Excluded: hosting, account credentials, deployment, security audit and support calls.
Proof to build: a sanitized sample project that a second person can run from its README.
Delivery: a versioned ZIP plus browser-readable source. Test both in a clean folder.
License: choose and include a license for material you own; retain upstream notices.
Support: self-serve documentation and issue reporting; no response-time promise.
Updates: only the purchased or downloaded version, unless a later promise is made.

## Price and cost hypothesis

An illustrative one-time price is EUR 19 excluding taxes. This is not a published
offer or a recommended market price. Direct platform/fulfillment cost is assumed
EUR 1; model cost EUR 0.50; expected support/refund cost EUR 3; acquisition cost
EUR 4. With EUR 19 net revenue, gross profit before support/acquisition is
EUR 17.50; contribution is EUR 10.50. The assumptions need actual evidence.
Fixed work, payment timing and income taxes are not included in that contribution.

## Product page sketch

**Give the next developer a place to start.**

Five editable templates help you explain how your project runs, what it needs
and what still needs work. Start with the filled example, replace its details
with your verified commands, then ask a collaborator to follow your handoff.

Inspect the sample before downloading. Hosting, code fixes and implementation
support are outside this pack. Do not publish a purchase button before checkout,
receipt and delivery have all been tested.

## Bounded test

Prepare one tutorial showing a real, sanitized before/after handoff. Publish only
through an authorized channel. Observe for 14 days with EUR 0 paid-media spend.
Record page visits, sample downloads, first-task completions and questions with
consent; use aggregate counts, never names or secrets in campaign URLs.

The initial learning target is three independent recipients attempting the first
task. This is a test threshold, not an expected result. If recipients cannot find
or run the first step, fix the pack. If fewer than three try, improve the audience
or distribution before interpreting price sensitivity. Do not infer demand from
page views alone.
