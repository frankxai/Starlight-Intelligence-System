# Constellation Protocol & Pack Ledger — Page Spec

Date: 2026-08-14  
Route: https://starlightintelligence.org/constellation  
Owner: Starlight platform team

## Product job

Let an operator, builder, or reviewer inspect the public trust chain behind the
ten-house / fifty-agent Starlight Constellation without confusing a profile,
prompt, eval fixture, or downloadable manifest with runtime authority.

## Domain boundary

- .ai owns story, visual exploration, canonical public dossiers, and the
  browser-local swarm builder.
- .org owns protocol, provenance, content hashes, pack-state truth, and public
  downloads.
- .academy owns composition curriculum and operator practice.
- The canonical identity source remains starlight-agent-army-architecture;
  every website is a generated projection.

## First viewport

The first viewport must show:

1. the exact scale of the release;
2. the structural-only / live-eval-not-run boundary;
3. the public/private and authority boundary;
4. short canonical, projection, release, capability, and visual digests;
5. a direct route to the packaging ledger and protocol JSON.

## Information architecture

1. Release trust envelope.
2. Exact portfolio counts.
3. Six-step trust chain.
4. Packaging ledger with ready, preview, absent, and not-listed states.
5. Nine immutable public manifests spanning portfolio, provenance, protocol, agent, skill, plugin, and marketplace receipts.
6. Ten house ledgers with all fifty visual and cryptographic receipts.
7. Three-domain public surface map and SIP attestation.

## Visual system

- Basalt field with a restrained evidence grid.
- Fraunces for institutional headings, Inter for prose, JetBrains Mono for
  receipts and states.
- Cyan means cognition/data lineage; amber means human authority/provenance;
  green means a structural artifact is present; coral means held or absent.
- Portraits remain evidence-linked identity applications. All labels, hashes,
  statuses, and controls are rendered in code.
- No WebGL, orbit animation, sound, decorative node web, or fake terminal.

## Responsive and accessible behavior

- Desktop house entries use a five-column ledger.
- Tablet collapses receipts and authority boundaries into a second row.
- Mobile uses a portrait/identity header followed by full-width skill, receipt,
  and boundary rows.
- One H1; semantic tables where appropriate; descriptive image alternatives;
  44px navigation targets; visible focus; reduced-motion route.

## Performance budget

- Static route and static JSON downloads.
- Fifty owned WebP portraits, lazy-loaded by next/image.
- No client component, runtime API, analytics SDK, or 3D dependency for this
  route.
- Zero private-memory, credential, local-path, or runtime-lease fields.

## Release gates

- Compiler verifies the 10-house / 50-agent count and every visual SHA-256.
- Focused ESLint and TypeScript pass.
- Production build passes.
- Desktop/mobile browser inspection shows zero overflow and no failed images.
- Design evidence scores at least 26/30.
- Vercel preview is verified before any production promotion.
