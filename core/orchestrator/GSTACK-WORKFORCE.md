# GStack Workforce Route Map

> Canonical SIS map for using GStack as Frank's external operating team.

## Strategic stance

GStack should be absorbed as method and routing, not vendored as code.

- SIS decides when to use each GStack specialist.
- ACOS turns those specialists into creator, venture, and product workflows.
- GStack remains installed as an external skill pack and browser/runtime tool.
- Harnesses execute by fit: Claude for canonical implementation, Codex for adversarial review, Gemini for long context, Antigravity for swarm-scale work, Grok for high-context TUI plus personal excellence layer.

## Priority project recipes

### Starlight Intelligence System

Goal: keep substrate truthful, governed, and shippable.

Chain:

`/health -> /plan-eng-review -> /review -> /cso -> /document-release -> /retro`

Evidence:

- `npm run lint`
- targeted substrate tests
- harness status contradictions
- security/trust notes
- docs updated or stale-doc list

### Agentic Creator OS

Goal: turn creator/business workflows into repeatable venture factory moves.

Chain:

`/office-hours -> /plan-ceo-review -> /plan-devex-review -> /spec -> /review -> /qa-only`

Evidence:

- workflow YAML exists
- ACOS lint passes
- command/skill routing says when to use GStack
- examples for business, dev, content, launch

### Arcanea AI App

Goal: visual/product quality and app correctness.

Chain:

`/plan-design-review -> /plan-eng-review -> /review -> /qa -> /benchmark`

Evidence:

- type-check passes
- browser proof for top routes when server is available
- design and performance notes

### FrankX Website

Goal: public-facing brand and conversion quality.

Chain:

`/plan-ceo-review -> /plan-design-review -> /qa-only -> /benchmark -> /document-release`

Evidence:

- type-check passes
- first-screen QA
- copy/offer clarity
- performance risk

## Stop conditions

Stop and escalate when:

- substrate docs claim operational parity while status files say scaffold/pending
- Kenya/personal material crosses into shared core without explicit SIP partition
- launch claims lack browser evidence
- security risk is asserted without exploitability reasoning
- a workflow produces no artifact path, no falsifier, or no owner

## Report format

Every GStack-driven SIS report should include:

- objective
- chain used
- repos/projects touched
- evidence run
- strongest finding
- next 3 actions
- unresolved blockers
