The most consequential architecture move

One log. Six vaults as projections.

Every write to memory is an appended, signed event. The vaults, the palace, the console graph, the search index and the receipts ledger are rebuilt from that log by one runner. Nothing is edited in place. Deletion is a tombstone and a replay. The projections on this page are computed from the log in the page, so what you see is the mechanism itself rather than a picture of it.

Erasure without editing history
1tombstone

Append, never edit

A tombstone event names the atom digest, the requester and the legal basis. The original event stays in the log; the log does not lie about what it once held.

2replay

Every projection forgets

The runner replays and skips tombstoned subjects. Vaults, palace, index, graph and the console lose the atom in one pass. No projection can keep a copy the log did not sanction.

3shred

Receipts keep their digest, lose the body

Content is encrypted per subject; erasure destroys the subject key. A receipt that cited the atom still verifies against its subject.digest, and nobody can read what it was.

What is real and what is prototype. Real today: append-only JSONL is the primary memory substrate (Board record 2026-05-23; migration 168 of 168 atoms), the work graph is an event log with ten event kinds (src/work-graph.ts), the receipts ledger appends one JSONL line per receipt (src/mcp-server-v01.ts), and AGENTS.md already describes the vaults as event-sourced JSONL truth. Prototype: one envelope for all three logs, the projection runner, tombstone and consent event kinds, per-subject keys, and the checksums. The move changes where truth lives, so it is a Board question; the proposal is section 7 of 2026-09-21-convergence-v4.md. Every number on this page is an example.
