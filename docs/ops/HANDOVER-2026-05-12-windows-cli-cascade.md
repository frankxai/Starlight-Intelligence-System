## What Changed This Session — bug cascade

### Bug 1 (commit 6f75329) — KDL `command` as body node, not attribute
- **Symptom**: `arc sis` opened 5 panes as plain shells, no auto-launch.
- **Root cause**: my generator wrote `pane { command "claude" args "..." }` but Zellij KDL requires `pane command="claude" { args "..." }`. Body-node `command` is silently ignored.
- **Fix**: rewrote `Format-LaunchBlock` in `generate-layouts.ps1`. 24 layouts regenerated.

### Bug 2A (commit 4f2c74f) — `default_shell "pwsh"` in zellij config killed sessions
- **Symptom**: `arc` (no args) opened cockpit then printed "Bye from Zellij!" immediately.
- **Root cause**: yesterday's `install-shell-environment.ps1` added `default_shell "pwsh"` to `~/.config/zellij/config.kdl`. Zellij 0.43.1-win32 cannot keep pwsh alive in a pane via that directive — likely shim/CMD vs exec mismatch in the Windows port.
- **Fix**: restored config from `config.kdl.bak-202605111753`. Updated installer to NEVER add the directive. Windows Terminal default = pwsh already, so panes inherit pwsh implicitly via parent process.

### Bug 2B (commit 4f2c74f) — `--layout FILE --session NAME` semantic trap
- **Symptom**: `arc sis` said "Session 'sis' not found. The following sessions are active: marvellous-xylophone".
- **Root cause**: per `zellij --help`, when `--layout` is combined with `--session`, layout is added AS A NEW TAB to existing session NAME — fails if NAME doesn't exist. To always create, use `--new-session-with-layout` (short: `-n`).
- **Fix**: `arc` function now invokes `zellij --session $Project --new-session-with-layout $LayoutFile`.

### Bug 3 (commit faf114e) — npm `.cmd` shims fail CreateProcessW
- **Symptom**: Zellij thread panic, OS error 193: "%1 is not a valid Win32 application" for `codex resume --last`.
- **Root cause**: `codex`, `gemini`, `opencode` are npm-installed `.cmd` shims at `~/AppData/Roaming/npm/`. Zellij's CreateProcessW resolved bare `codex` to the extensionless bash-style script (for WSL/Git Bash), which Windows can't exec.
- **Fix**: 8 cockpit profiles updated — `codex`/`gemini`/`opencode` commands now carry explicit `.cmd` extension. `claude` stays bare (it's `.local/bin/claude.exe` — real PE binary). Regenerated 24 layouts.

### Bug 4 (commit faf114e, found while fixing 3) — Audit tab still had body-node syntax
- **Symptom**: would have surfaced as silent failure to spawn `pwsh -NoExit -File tail-audit.ps1` in the Audit tab.
- **Root cause**: the Audit tab block in `_template.kdl.tmpl` was hardcoded (not generated by `Format-LaunchBlock`), and I missed updating it when I fixed Bug 1. Same body-node mistake.
- **Fix**: template `pane name="audit-tail" cwd="..." command="pwsh" { args ... }`.

## Session Wisdom

### Prompts That Worked

- **"also explain how it works?"** alongside reporting a bug — forced both diagnostic AND pedagogical response. Made the explanation of arc + zellij + KDL composition land as documentation, not afterthought.
- **Pasting the full error verbatim** ("Error occurred in server: Thread 'pty' panicked... error 193") — error 193 + "is not a valid Win32 application" + the full path Zellij tried to exec made the root cause diagnosis instant. No guessing.

### Technical Choices Validated

- **Windows CreateProcessW + .cmd files** — bare CLI names work for `.exe` (Windows tries `.exe` first by default) but fail for `.cmd` shims when invoked via CreateProcessW without extension. The extensionless `codex` file at `~/npm/codex` (bash script for WSL) shadowed `.cmd` in PATH resolution. Always use explicit `.cmd` for npm-installed Windows CLIs in any KDL/exec context.
- **`--new-session-with-layout` is the create-only flag** in Zellij 0.43.1. `--layout FILE --session NAME` means "attach to NAME, add layout as tab" — a subtle semantic trap that costs hours if not noticed.
- **`default_shell` directive in zellij config is broken on Windows** for `pwsh` (cmd/shim mismatch). Don't set it. Let panes inherit the parent terminal's shell.

### Patterns Discovered

- **Cascade-of-bugs in a single logical change**: enabling auto-launch in cockpit profiles surfaced FOUR bugs (KDL syntax, default_shell, --session flag semantics, .cmd extension) — each invisible until the prior was fixed. Lesson: when a multi-layer change "doesn't work," fix one layer, retest, fix next layer. Don't try to fix everything in one shot.
- **Smoke tests that check cwd= regex don't catch KDL semantic errors** — current `cockpit-zellij/test/smoke.ps1` validates file structure but not zellij parse-correctness. Add `zellij --check-config` or similar layout-parse step to the smoke harness next. Without it, every new KDL feature is a Frank-discovers-it-in-his-terminal bug.
- **Error code 193 on Windows** = "wrong PE format" = .cmd/.bat invoked as if .exe. Diagnostic shortcut: anyone seeing 193 should immediately check for `.cmd` shims.
