## Distribution Architecture

Use three channels, each with a different job:

| Channel | Best for | Rule |
| --- | --- | --- |
| GitHub Releases | Versioned plugin bundles, checksums, changelogs, source archives | Every public bundle gets a release artifact and validation log |
| `starlightintelligence.org` | Intelligence-system downloads, SIP packages, agent/plugin bundles | This should be the primary download home for system modules |
| `frankx.ai` | Founder brand, consulting, AI architect offers, business command downloads | This should explain outcomes, route buyers, and link to releases/downloads |

Recommended public flow:

1. Visitor lands on `frankx.ai` for the founder/business offer.
2. Technical users go to `starlightintelligence.org/downloads` for system modules and plugin bundles.
3. Each download links to a matching GitHub Release with version, checksum, install command, release notes, and support path.
4. Private or sensitive plugins stay in the personal marketplace until redacted and licensed for release.

## Guide Experience

Every plugin bundle should ship with the same user journey:

1. Choose mission: business command, revenue, creative studio, enterprise AI, health, prompt/eval, or agentic ops.
2. Install verified bundle: one command, one checksum, one clear compatibility line.
3. Run first workflow: a prompt starter that produces a real deliverable in under ten minutes.
4. Validate output: checklist for evidence, privacy, claims, attribution, and release readiness.
5. Upgrade path: where to get templates, cohort, consulting, or the full Starlight system.

## Validation Standard

Before any plugin becomes public:

1. `python C:\Users\frank\.codex\skills\.system\plugin-creator\scripts\validate_plugin.py <plugin-path>`
2. Install from the marketplace with `codex plugin add <plugin>@plugins-cli`.
3. Confirm `codex plugin list` reports `installed, enabled`.
4. Validate the installed cache copy under `C:\Users\frank\.codex\plugins\cache\plugins-cli\<plugin>\0.1.0`.
5. Open a fresh Codex thread and confirm the skill appears in available skill context.
6. Run at least one representative workflow and save the resulting artifact or transcript.
