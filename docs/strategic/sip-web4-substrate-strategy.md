## Recommended IP / Open Core Posture (Ethereum Model)

Ethereum succeeded because:
- Open protocol/spec (yellow paper) → multiple clients, massive adoption, network effects.
- Value captured in layers above: dapps, infrastructure services (Infura = "steward" ops), enterprise deployments, tokens for coordination, premium tooling/education, private/permissioned chains that still honor the standards.
- Core clients open (geth etc.), but companies productize hardened production, hosted, or enterprise features.
- No one "owns" the chain, but participants capture enormous value.

**Apply exactly here:**

### Open (Adoption Flywheel — like the protocol spec)
- **SIP.md** (the contract: file contract, attestation "Built on SIP", sovereignty clause §5, command taxonomy, encoded-self boundary). MIT.
- Basic reference scaffolds, templates (vertical-starter, domain-stack-starter), command reference implementations (`.claude/commands/` protocol/alliance/vertical tiers). MIT.
- AGENTS.md archetypes (base), orchestration patterns, memory bus concepts.
- Attestation network effect: every estate that ships strengthens the substrate and the client's credibility ("Built on SIP" provenance like on-chain receipts). This is the "public good" layer.

**Why open the core?** 
- Adoption creates the moat (more eyes, more improvements promoted back, more "estates" that make the next one cheaper — exactly the factory economics in the proposal).
- Like Ethereum clients: anyone can run a node/estate. Standards win.
- Current LICENSE + SIP already do this correctly.
