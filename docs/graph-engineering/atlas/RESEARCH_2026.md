# Agent graph engineering benchmark — 2026-08-29

Only primary or official sources are used here. The purpose is not to choose a winner; it is to extract implementation patterns Starlight can compose without importing another control plane.

| System | Implementation pattern worth copying | Boundary for Starlight |
| --- | --- | --- |
| [Google ADK workflow graphs](https://github.com/google/adk-python/blob/main/docs/guides/workflow/graph/index.md) | Directed workflow graphs compile and validate before execution; validation covers start nodes, reachability, duplicate edges, defaults, cycles, and schema compatibility. Parallel execution ordering is deterministic. | Adopt the compiler discipline and deterministic joins. Keep the SIS graph model harness-neutral. |
| [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence) | Per-step checkpoints enable human interrupts, resume, time travel, and fault recovery. A separate store handles cross-thread memory. | Preserve the state/memory separation. Do not make LangGraph another estate scheduler. |
| [Microsoft Agent Framework human-in-the-loop](https://learn.microsoft.com/en-us/agent-framework/workflows/human-in-the-loop) | Pending requests and responses survive checkpoints so approval can resume later. | Model Human Gate requests as typed state with correlation IDs, not prose alerts. |
| [Temporal](https://docs.temporal.io/) | Durable execution resumes after process, network, or infrastructure failure, including long waits. | Candidate backend for high-value long-lived routes after the portable work contract stabilizes. |
| [OpenAI Agents SDK](https://openai.github.io/openai-agents-python/) | Minimal primitives: agents/tools, handoffs, guardrails, sessions, human approval, and tracing. Handoff filters control transferred context. | Implement these features in the adapter plane; avoid coupling the estate graph to one SDK. |
| [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system) | Multi-agent systems are effective for valuable parallel work, but use far more tokens. Their system scales delegation by task complexity and shares concise results back to the lead. | Encode effort classes and fan-out caps. Prefer deterministic pre-passes and gist write-backs. |
| [GitHub Agentic Workflows](https://github.blog/changelog/2026-06-11-github-agentic-workflows-is-now-in-public-preview/) | Human-readable Markdown compiles into standard Actions and inherits existing runner policies. Earlier preview material emphasizes read-only defaults and safe outputs. | Compile Starlight loop specs into existing schedulers rather than adding a third scheduler. |
| [GitHub issue automation controls](https://github.blog/changelog/2026-07-23-agent-automation-controls-in-github-issues-in-public-preview/) | Automated changes carry rationale and confidence; medium/low-confidence changes can wait as suggestions. | Add rationale, confidence, and action class to Human Gate proposals; approval is workflow convenience, not the security boundary. |
| [Langfuse agent graphs](https://langfuse.com/docs/observability/features/agent-graphs) | Aggregated traces collapse repeated steps and cycles; expanded traces show the exact unrolled run. | Provide both architecture and execution projections from the same trace data. |
| [OpenTelemetry GenAI conventions](https://opentelemetry.io/docs/specs/semconv/registry/attributes/gen-ai/) | Portable attributes cover agent, conversation, tool, and token usage. The standard warns that captured content and tool data can be sensitive. | Align names but collect content only by explicit policy; redact at ingestion. |
| [A2A concepts](https://a2a-protocol.org/latest/topics/key-concepts/) | Agent Cards describe identity/capability, tasks carry state, and artifacts are distinct from conversational messages. | Export Agent Card projections and artifact receipts; do not treat cards as authoritative runtime state. |
| [CrewAI Flows](https://github.com/crewAIInc/crewAI/blob/main/docs/v1.15.12/en/concepts/flows.mdx) | Start/listen/router decorators and persisted flow state give a simple event-driven authoring model. | Useful authoring inspiration; compile into Starlight types rather than adopting another runtime. |
| [Strands graph](https://strandsagents.com/docs/user-guide/concepts/multi-agent/graph/) | Dependencies, conditional routing, nested graphs, cycles, limits, timeouts, and remote A2A agents are first-class. Its multi-inbound behavior requires explicit attention. | Starlight requires explicit AND joins for reducers; never inherit ambiguous OR semantics. |
| [Pydantic Graph](https://github.com/pydantic/pydantic-ai/blob/main/docs/graph.md) | Strongly typed state machines and graph builders; its own guidance says graphs are not necessary for every job. | Adopt typed authoring ideas. The 2026 removal of built-in graph persistence makes it unsuitable as the durable backbone. |
| [Graphiti](https://help.getzep.com/graphiti/getting-started/welcome) | Incremental temporal context graphs update relationships and facts without batch recomputation. | Derived memory index for approved episodes; never fleet work SSOT. |
| [Microsoft GraphRAG](https://github.com/microsoft/graphrag/blob/main/docs/index.md) | Extracts entities/relationships/claims, builds hierarchical communities, and supports local/global/DRIFT retrieval over a corpus. The project warns indexing can be resource intensive. | Use selectively for corpus intelligence and holistic questions, behind an admission budget. |
| [MCP authorization](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization) | Authorization is a transport concern with protected-resource metadata and OAuth-compatible discovery. | Keep tool authorization at the MCP boundary; never pass broad credentials through prompts or memory graphs. |

## Competitive conclusion

Most systems optimize one layer: authoring, runtime, memory, tracing, or automation. Starlight should integrate those layers through portable contracts while leaving execution to the best harness for the job. Its product surface is the governed graph, the proof plane, the context compiler, the domain route packs, and the outcome economics.

The defensible benchmark is not “number of agents.” It is:

`verified outcome value / (tokens + compute + cycle time + human decisions + risk)`
