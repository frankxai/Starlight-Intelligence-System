# Next Era decision memo · v1

Issue [#197](https://github.com/frankxai/Starlight-Intelligence-System/issues/197) sets the mandate. The dated [claim map](claim-evidence-2026-09-23.md) is the evidence boundary for this decision. This memo changes public explanation and product emphasis; it does not amend the SIP sovereignty clause or the locked ten Intelligence Systems taxonomy.

## Decision

**Category today:** Starlight is local-first intelligence infrastructure for owner-directed venture portfolios. Its current reference build offers local memory and attestation tools, passing Foundry skill-package paths, and governed work models; a full packaging path and integrated portfolio product are still being assembled.

**Enemy:** lost intelligence: inaccessible decisions, fragmented context, duplicated work, capability trapped inside projects, and vendor-bound history.

**Brand and product thesis:** *Intelligence should compound.* A useful test is whether a verified capability from venture N can reduce work or improve an outcome in venture N+1 while both ventures remain independently operable. Current main does not yet prove that result.

**Mechanism:** Create → Capture → Verify → Transfer → Operate → Learn. Verification and transfer are explicit gates. A copied prompt without provenance, permission, and a later outcome is not measured compounding.

**Public primitives:** Command, Memory, Teams, Capabilities, Operations, Transfer, Evidence. These are visitor-facing grouping terms over existing code, not a replacement taxonomy for `STACK.md`. Network remains a research/horizon direction; Academy is a learning and distribution layer.

**Brand relationship:** Starlight holds the substrate and operating infrastructure. Ventures create their own products, value, knowledge, and capabilities under their own authority. FrankX is the founder/operator and public exploration surface. Arcanea is imagination, culture, worlds, art, and symbolic IP under its own canon. Starlight Notes/Horizon Vault is the public, long-duration knowledge and values archive, with a strict boundary from private memory.

**Time horizons:** Now = local working primitives with code and tests. Next = integrated portfolio command and verified cross-venture transfer. Generations = durable intelligence, civic and scientific contribution, and a flourishing civilization. The final horizon is a mission, never a shipped feature.

**Naming:** Use literal UI nouns: Ventures, Decisions, Work, Memory, Teams, Capabilities, Evidence. Reserve constellation and light for editorial explanation. Do not rename the existing SIP, Queen, or ten-system substrate to force a marketing model.

**Primary site action:** “See the evidence” to `/proof`. `/proof` gives developers direct code and test paths, and then a working `/quickstart`. Creators can enter through `/badge` and public Notes; founders/operators through portfolio posture; partners/investors through the one-page business thesis. None requires a claim of deployed autonomous operation.

## Site consolidation

Keep `/architecture`, `/constitution`, `/quickstart`, `/protocol`, `/research`, and `/vaults` as the deeper existing routes. Rebuild `/` around category, problem, mechanism, current proof, compounding requirement, venture independence, sovereign architecture, horizon, and one primary action. Add only three missing entry points: `/story` for the origin and seven reusable narrative artifacts, `/proof` for the status/evidence bridge, and `/notes` for a privacy-safe public artifact model. Reuse `/constitution` for the portfolio relationship rather than creating a competing constitution.

The current homepage proof animation is illustrative but presented as verified. Remove it from the evidence path. Inventory counts and seed workspace data will not be used as outcome metrics.

## Design direction

Derivation: the source voice is direct, technical, warm, and pattern-aware (`CLAUDE.md`; `genius/profile-frankx.md`), the product requires inspectable proof, and the long horizon requires restraint. Use the existing site type and identity while the cross-repo brand foundation is founder reviewed. **Evidence Mode** uses exact diagrams, source paths, readable tables, and dated status. **Horizon Mode** uses editorial scale, generous space, and precise celestial reference. One mark and one visual idea per composition; no new logo claim.

The seven narrative artifacts will be independent exact-text components with web and export compositions. The diagrammatic pieces are Tier C assets because exact labels and relationships are the subject. The cover and origin must show the real Starlight mark or a genuine evidence object, rather than decorative stars. Their CSS and export rules must keep text semantic and selectable.

## Business test

The operating hypothesis is that verified reuse lowers time-to-context, duplication, and time-to-working-product or improves quality for a later venture. No TAM, revenue, partnership, or customer claim is inferred from repository structure or seeded workspace data. North star: verified reused capabilities with measured venture outcome gains. Falsifier: if reusable capability records do not produce measurable improvements after controlled transfer, the compounding mechanism is a documentation practice, not a venture advantage.

## Decision boundaries

- This is an operational narrative layer. Changes to SIP protocol, file contracts, sovereignty, attestation rules, or ten-system taxonomy require a separate substrate board and PR.
- Public Notes can ingest only explicitly curated public records. Private vault and founder profile material stays out of the public build.
- Existing brand identity stays intact; the seven-artifact system is a reusable editorial/product layer pending founder identity review.
- Open PRs #189, #195, and #196 are not in `main`; their unmerged claims do not upgrade this status map.
