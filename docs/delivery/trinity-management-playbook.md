# Trinity Management Playbook — Alliance + Commercial Advanced Tech / Agent Army Delivery

> Trinity is the canonical first alliance + first full estate instance. Manage it with strict alliance hygiene (governance, attribution, cycles) *plus* a separate commercial services layer for the "build and run their advanced agent army using the SIP substrate" delivery. This is how we deliver world-class advanced tech while preserving sovereignty and the protocol posture.

**Context**: Per ALLIANCE.md, Trinity is coordination among sovereign nodes (Frank as architect + allied nodes: sovereign-creator, protocol-defender, implementer). The sovereign-creator node's company/product ("Trinity AI" or equivalent) is that node's *vertical* — not the alliance. The alliance is the shared protocol layer.

The big client pull for Trinity (and similar) is "help us set up and run this agent army" at production grade. That is delivered as commercial engagement on top of the alliance substrate.

**Non-negotiables** (from SIP §5, ALLIANCE.md, CANON.md, encoded-self rule):
- Each node full decision rights in its declared domain.
- Cross-node artifacts carry "Built on SIP" with all contributing nodes.
- Encoded-self artifacts (personal voice clones, genius profiles, identity vectors, vault-specific paths) are non-licensable and non-transferable.
- Canon (if used): CC-BY-NC terms travel; commercial use requires license.
- Advice ≠ override. Frank's input is architectural depth, not command.
- Exit always available; attribution history immutable.

## Alliance Layer (Governance — Always Active, Per ALLIANCE.md)

### Node Declarations (YAML schema, kept in private/alliance-register.md or equivalent)
Every node has:
- name, role (architect / sovereign-creator / protocol-defender / implementer / ...)
- domain (one sentence — the layer this node owns)
- decision_rights (list of artifact or decision classes)
- advises_on (list where node contributes but does not decide)
- repos
- public_surface
- commitment_cadence (weekly / biweekly)

Missing fields = node not ready. Do not paper over.

### Cadence & Rituals
- Weekly or biweekly cycles (set at forge, preserved).
- /alliance-reflect at cycle close: each node reports (what shipped, what blocked, what next), commitments extracted, synthesis (Lumina or chosen).
- /alliance-decide at any fork: collapses option space, assigns per domain map, extracts the call. One node owns the decision per the map; others advise. No votes.
- /sip-attest on every cross-node artifact.

### Frank's Posture in the Alliance (per ALLIANCE.md)
- Help freely and abundantly for architectural guidance and substrate work.
- No ownership claim on the alliance or its artifacts.
- Attribution via SIP is the sole compounding mechanism.
- Time is gifted for the alliance layer; commercial delivery (agent army build) is separate (see below).

### Example Trinity Instance (high-level, private details in register)
- Nodes: Frank (architect) + sovereign-creator + protocol-defender + implementer.
- The alliance coordinates shared artifacts and substrate evolution.
- The sovereign-creator node's company is their vertical — they own the product economics, the specific estate instance(s), the client relationships for "Trinity AI".

**Failure modes to watch**: Conflating the alliance with one node's company. Silent composition. Consensus theater (the protocol uses domain-map ownership + advise, not votes). Stalling cycles (silence is a breach).

## Commercial Delivery Layer (Agent Army / Advanced Tech — Separate SOW)

This is the "Estate Factory / Olympus" engagement for Trinity (or any high-value client wanting the full Mind + Mesh + Steward).

**Scope**: Commission and stand up their production-grade agent army (sovereign intelligence estate) using the full SIP substrate + advanced harnesses + Frank architectural depth. Pilot (Mind + core swarm) → Scale (Full Mesh) → Standing (Steward retainer + evolution).

**Separate from the alliance**: The alliance governs the *coordination among nodes*. The commercial SOW governs the *build and operation of the specific technical estate/army* for the sovereign-creator node's vertical (or the alliance as a whole if shared).

**Typical SOW elements** (customize per engagement):
- Blueprint phase (4-layer: Persona, Topology, Kernel, Modules) grounded in their Genius/Profile + Vision (if applicable).
- Provision/scaffold (sovereign-spawn or estate-os profile fork, configured to blueprint, protections wired).
- Build phase: full Mind (10-IS + Genius grounding) + Mesh (orchestrator patterns, /si multi-CLI routing, Hermes, claws, swarm consensus, memory bus, voice, attestation, evals) using the best current lanes (Antigravity for async/browser/agent swarms, Claude for architecture/council, etc.).
- Pilot with live client workflows.
- Scale + validation (evals, self-learning, more modules).
- Handover + Steward retainer (ops, health, evolution, Frank access for major moves, board facilitation).
- IP terms: Client/vertical owns their tuned estate, data, custom agents, running instance. Starlight/Frank owns the generalized process, any IP brought or promoted back to substrate, delivery IP. Encoded-self boundaries strictly enforced. Full export on exit.
- Pricing: Build fee (scoped to Pilot-to-Standing) + monthly retainer for Steward phase.
- Governance: Alliance cycles continue in parallel for coordination; commercial SOW has its own milestones + board gates for technical decisions.
- Attestation: Ambient + explicit on all shipped artifacts.

**Advanced tech delivery specifics for Trinity**:
- Use the substrate at its best: ORCHESTRATION_ENGINE (swarm coordination, patterns, self-learning), /si + cli-tool-router (preserve context across lanes, receipts), antigravity harness + swarm-protocol (async, browser, agent-manager), full claws suite, Memory Bus + vaults + Veil, Genius/Profile wired in, 10-IS + any relevant domain sub-stacks, voice operator, proving ground evals, yolo/hive for high-autonomy work.
- Route via /si model: send appropriate work to the strongest current tool/lane for that subtask (e.g., complex browser/agent orchestration to Antigravity, deep council synthesis to Claude, fast scratch to OpenCode, etc.).
- Custom work: any Trinity-specific kernels, topologies, or production patterns are built here and (generalized parts) promoted back.
- Quality: Every high-stakes move board-tested. /sip-attest refuses decoration. Continuous evals on their mesh.

**Frank's role in the commercial layer**:
- Architect + forward-deployed lead (blueprint, SOW, major sign-offs, taste/voice, custom advanced tech).
- Command center sequences; execution via claws + routed CLIs.
- Ongoing in retainer: architectural guidance on evolution, board facilitation.

**Success metrics for the commercial engagement**:
- Trinity (their vertical) has a live, attested, compounding agent army that handles real work.
- They (or their operator) can describe it, point to outputs, and run day-to-day evolution.
- IP boundaries held; sovereignty intact.
- Learnings from the build promote back (makes the next estate cheaper and the substrate stronger).

## Risks & Mitigations (Trinity-specific)

- **Conflating alliance with the product company**: Keep separate mental and contractual models. Alliance = coordination protocol. Commercial = build/ops services for their vertical's army.
- **Scope creep on Frank's time**: Alliance help is abundant/gifted per posture. Commercial delivery is scoped in SOW + retainer. Use boards and clear commitments.
- **IP leakage**: Enforce encoded-self + Veil + private/ strictly. Document boundaries in SOW and runbooks.
- **Quality drift**: Pilot must ship real attested work before scale. Continuous evals + board on major moves. Self-learning loops in the orchestrator.
- **Sovereignty theater**: Actual export tests + client operator training in the handover. They must be able to run it without you.
