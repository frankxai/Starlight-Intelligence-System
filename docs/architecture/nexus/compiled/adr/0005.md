# progressive-runtime-adoption

Status: proposed

## Context

The accepted architecture favors Cloudflare persistent entities and preserves current experience and business owners.

## Options

- Cloudflare durable coordination with existing Vercel/Supabase surfaces
- Only local daemon and manual handoff
- Assembled coding harness plus persistent cloud workspace plus GitHub PR workflow
- Experimental Sandbox-backed managed executor

## Decision

Cloudflare durable coordination with existing Vercel/Supabase surfaces

## Consequences

Retain manual/local handoff and compare against an assembled coding harness plus persistent cloud workspace plus GitHub PR workflow on the same frozen tasks, models, budget and review criteria. Evaluate one Sandbox executor after continuity works; snapshot/process limits, isolation and billing must be proven. Preserve one durable workflow owner and existing gateway default; no second wallet.

## Revisit

Held-out missions fail to reduce reconstruction/review time at equal completion quality against the assembled baseline, or the proposed pilot repeat-use/renewal gate is missed. Stop breadth expansion and repair the workflow.

Evidence: registry
