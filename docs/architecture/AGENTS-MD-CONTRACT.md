# The AGENTS.md contract

**Status:** proposed. Touches the SIP § 1 file contract, so `/starlight-board` runs before tag or merge, per `CLAUDE.md` § substrate-tier governance gate.
**Scope of this change:** this repository only.
**Owner:** `agent:starlight-cto` (topology) with `agent:starlight-caio` (substrate)

---

## The decision

**One `AGENTS.md` per repository. Never one central copy.**

`AGENTS.md` is not documentation. It is a harness artifact: the file an agent reads at session start because it is sitting in that working tree. A contract that is not in the tree is not read, so centralising it would delete it.

The opposite failure is also real: hand-maintained copies of shared rules drift. Copies drift and generation does not. So the file lives in each repo, but the shared part of it has one source.

## Bands

An `AGENTS.md` carries generated bands and one hand-written band.

### Band A: inherited (generated, never hand-edited)

The shared rules: Frank's DNA, the five behavioural guardrails, decision discipline, the branch and PR protocol, multi-agent coordination, the attestation clause, and the non-waivable safety rules.

- **Source:** `docs/architecture/agents-md/band-a.md`, authored by hand. It is not scraped from `CLAUDE.md` or `VOICES.md`; `VOICES.md` stays the voice authority.
- **Fence:** the band sits at the top of `AGENTS.md` between these markers:

  ```markdown
  <!-- STARLIGHT:BAND-A:BEGIN v1 sha=<12 hex> — generated by scripts/agents-md-project.mjs, do not hand-edit -->
  ...
  <!-- STARLIGHT:BAND-A:END -->
  ```

  `sha` is the first 12 hex characters of the SHA-256 of the body the generator wrote.

### Band C: repo-local (hand-written; the generator never touches it)

Everything outside the fence. Build and test commands, ports, local gotchas, and contracts that exist only here.

**Band C outranks Band A on any conflict inside its own repo**, and Band A's preamble says so. A generated contract that could silently override a local safety gate would be worse than no generated contract.

### Band B: not in this change

A per-company projection (owner, accountable seat, brand pin, tier) is designed as Band B. It depends on a company registry that is not public yet, so this change ships no Band B and the generator does not know about one.

## The check

```bash
node scripts/agents-md-project.mjs           # check only (the default): exit 1 on drift, never writes
node scripts/agents-md-project.mjs --write   # local: regenerate the fence, keep Band C
npm run agents-md:check                      # the same check, run inside npm test
```

**Check-only is the default.** `npm test` (via `test:operational`) runs it, and therefore so does CI. Nothing in CI writes to the tree. The check fails when:

- **The band is stale or missing.** The fenced body differs from `docs/architecture/agents-md/band-a.md`.
- **The band was hand-edited.** The fenced body no longer hashes to its own declared `sha`. The fix is to change the source and run `--write`, never to edit inside the fence.
- **The band would leak.** The source matches the money, jurisdiction, or credential pattern. This is checked before anything is written.

Properties, covered by `test/agents-md-contract.test.ts`:

- **Band C survives byte-for-byte.** The generator strips the fence, keeps the rest, and re-emits A + C. Line endings are normalised to LF, and a leading BOM is dropped.
- **Idempotent.** A second `--write` changes nothing, which is what lets the check tell stale from fresh.
- **Line-ending agnostic.** CRLF and LF checkouts hash the same, so a Windows checkout and Linux CI agree.

## Standing against SIP Layer 1

SIP v1.1.1 § 1 lists `AGENTS.md` as "Voices / agent definitions" and `SKILL.md` as behaviour. Band A is behaviour landing in `AGENTS.md`.

This change does not amend § 1. § 1 constrains which files exist and which are required; it does not exhaustively list what may be written inside one. No file is added, removed, or made newly required. Restating the `AGENTS.md` row as the cross-harness working-tree contract is a separate, version-coupled change, because `src/version.ts` and `test/v80-platform-prompts.test.ts` both read SIP's version line. It gets its own board pass.

## `CLAUDE.md` vs `AGENTS.md`

These are orthogonal. `AGENTS.md` is the cross-harness contract (Codex, Cursor, Cline, Gemini, Grok, OpenCode); `CLAUDE.md` is the Claude-specific deepening. Band A does not rank one above the other. Each repo states that precedence in its own Band C.

## What this deliberately does not do

- It does not write into other repositories. Projecting Band A into sibling checkouts is a later change.
- It does not ship Band B or any company or estate registry.
- It does not change `CLAUDE.md`.
