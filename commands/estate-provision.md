`/estate-provision` is the canonical command for the provision/scaffold step in the Estate / Agent Army commissioning workflow (see `docs/delivery/estate-army-commissioning-workflow.md` and `docs/strategic/sip-web4-substrate-strategy.md`).

- Instantiating a new sovereign intelligence estate from the thin `starlight-estate-os` reusable composition profile (the maintained 80%).
- Applying the client's Genius-grounded 4-layer Blueprint (Persona/Naming skin, Topology/Swarm shape, Kernel/insight density, Modules) as the tuned 20%.
- Emitting an initial actionable Build Brief with 30/90-day targets, first Pilot workflows, and harness/claw setup.
- Intelligently dispatching the first construction wave across lanes via `/si` (context-preserving handoff packets + receipts).
- Wiring attestation, promotion commitments, and sovereignty boundaries from day zero.

This advances the Estate Factory (post 2026-06-16 Board PROCEED-WITH-REVISE R2/R3): every estate starts production-hardened and every estate makes the next one cheaper via the explicit promotion loop.

## Core Process (Exact)

1. **Profile Scaffold** — Compose the estate root from `templates/estate-os/` (README, AGENTS, SKILL, MEMORY, SOUL + inherited file contract). Create private/, ATTESTATIONS.md, cycle-0 state. Reference substrate pieces (never duplicate whole canon).

2. **4-Layer Apply** — Load the Blueprint (grounded in /discover-genius output + Freedom Path). Map:
   - Persona → voice/naming overrides in VOICES.md + tuned AGENTS.md
   - Topology → ORCHESTRATION_ENGINE patterns + yolo/hive/Claws mesh choices
   - Kernel → standard vs selective advanced/Luminor routing flags
   - Modules → base 10-IS + /spawn-domain-stack vertical sub-stacks + registration
   Emit tuned overrides only where client-specific.

3. **Build Brief + /si Dispatch** — Generate the brief. Then route:
   - Deep architecture / council synthesis → primary substrate lane (Claude)
   - Multi-file implementation / harness wiring → Codex
   - Long-context research / browser swarm actions → Antigravity or Gemini
   Always use `/si` (or the cli-tool-router skill) with handoff packets. Record receipts in operational vault + estate logs. Enforce token budgets and progressive loading.

4. **Attest + Sovereignty Lock** — Every output carries full "Built on SIP" (layers, version, estate, timestamp, swarm composition). High-provenance items go through explicit `/sip-attest`. Refuse any encoded-self leakage (SIP §5.7). Client ownership of tuned estate is declared in every relevant artifact.

5. **Factory Commitment** — Seed the promotion obligation in MEMORY.md / ATTESTATIONS.md: post-pilot, run /sis-forge + manual; promote generalized patterns (scaffolds, runbooks, configs, orchestration refinements) back to starlight-estate-os profile, core/ORCHESTRATION_ENGINE.md, claws/, templates/, docs/delivery/.

6. **Handoff** — Operator packet + initial Steward runbook stub (client voice). Verify against the world-class E2E checklist (client describes behavior + points to live attested outputs; mesh handles real multi-step without babysitting; memory compounds; gates held).

## Rules & Invariants (Non-Negotiable)

- **Sovereignty first (SIP §5)**: The estate owner retains full decision rights. This command facilitates; it does not own or override.
- **Encoded-self boundary (SIP §5.7)**: Client's Genius Profile, Freedom Path, voice, identity vectors, and vault-specific paths are non-licensable and non-transferable. Forks inherit pattern, never the person.
- **Attestation by default**: Real "Built on SIP" on every serious output. Ambient where possible; explicit `/sip-attest` for cross-party or board artifacts.
- **Thin profile discipline**: Anything not uniquely the client's belongs in the starlight-estate-os profile or substrate, not the estate. Promote aggressively.
- **Board gate**: Any substrate touch, topology/kernel change, or public commitment requires `/starlight-board` (or `/luminor-board`) first.
- **Layer routing**: Substrate-level moves (SIP, ALLIANCE, canon, file-contract) use architect voice + SIP attestation. Operational moves inside the estate use Frank DNA voice.
- **/si for dispatch**: All cross-CLI construction uses the router with context preservation and receipts. No raw shell for army build steps.
- **Promotion loop is structural**: The economics only work if every estate feeds the factory. This is recorded and auditable.
- **Alliance vs Commercial separation** (for Trinity-class): Alliance governance (cycles, attribution, /alliance-*) stays in ALLIANCE.md. Commercial estate build (SOW, blueprint, retainer) stays scoped here.
