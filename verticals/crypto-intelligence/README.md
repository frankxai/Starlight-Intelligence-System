## What this vertical is

Crypto Intelligence is the wrapper for sovereign cryptocurrency practice — the thinking layer that runs above wallets, exchanges, chain explorers, and DeFi protocols. It is **not** a trading bot, **not** an investment advisor, **not** a chain-analytics service. It is the cognitive scaffolding for someone who runs their own custody, makes their own thesis decisions, and refuses to outsource sovereignty.

The vertical is decomposed into **six Houses** (archetypal stances that organize crypto practice), each a sub-system that ships named output artifacts per command. The Houses-as-sub-systems primitive is on proof-of-pattern at v0.1 — only House of On-Chain ships in this round per Board R4 verdict. Full 6-House scaffold lands on v0.1-proof-pass.

This is a **public reference vertical**. Sovereign crypto practitioners fork it into their own private repo via `/sovereign-spawn` or `/spawn-domain-stack` and shape it to their thesis, their portfolio, their custody architecture, their on-chain practice.

## What this vertical is NOT

- **Not trading advice / not investment advice / not tax advice / not legal advice.** This is system architecture. Outputs frame decisions; jurisdiction-specific counsel signs off on instruments. The practitioner accepts capital risk; the substrate accepts no claim. (R5 non-advisory clause — universal across all Houses.)
- **Not a trading bot, not an execution layer.** No automated buying/selling. The vertical organizes thinking; execution stays with the practitioner.
- **Not chain-analytics-as-service.** Houses use chain-analytics tools (Dune, Etherscan, Nansen) as inputs; the vertical doesn't replace them.
- **Not a "smart money" follower playbook.** Whale-tracking is one signal; the vertical refuses to derive theses purely from on-chain wallet behavior.
- **Not algorithmic-gaming or wash-trading-aware-of-it.** Fake volume, sybil distribution, governance-vote-buying — all refused.
- **Not a substitute for the practitioner's lived practice.** This vertical organizes thinking; it does not replace the practitioner who has run their own custody, made their own thesis decisions, and lived through multiple cycles.
- **Not a generic playbook.** Every output is portfolio-specific, jurisdiction-specific, custody-specific. There is no "Crypto Intelligence answer" that ports across practitioners without re-grounding.

## How to use (v0.1)

### Run House of On-Chain commands

```
/crypto-onchain-flow-snapshot <wallet-slug>     # weekly wallet-flow + whale-tracking pulse
/crypto-onchain-wallet-trace <address>           # trace a single wallet's recent activity
/crypto-onchain-mev-audit <protocol-slug>        # MEV exposure audit for a protocol
/crypto-onchain-validator-econ <network-slug>    # validator economics summary
/crypto-onchain-contract-interaction <tx-hash>   # contract interaction trace + risk surface
```

Each command opens with the non-advisory disclaimer (R5), runs the protocol, ships an artifact carrying "Built on SIP" attestation.

### Run a full Houses-of-On-Chain flow

`/crypto-onchain-flow-snapshot` → `/crypto-onchain-wallet-trace` (drill into specific addresses) → `/crypto-onchain-mev-audit` (if positions interact with MEV-prone protocols) for a weekly on-chain pulse.

Run House of On-Chain for 1 week against actual practice. If 4-5 named artifacts ship in the week, Houses-as-sub-systems primitive is validated for crypto → proceed to scaffold remaining 5 Houses. If not, fall back to functional sub-systems matching People IS shape — re-iterate at PROPOSAL.md.
