# Music agent execution contract

This dated contract takes precedence over incompatible legacy Music IS agent assumptions for owned label operations. It changes no Starlight substrate or Arcanea lore. Seven existing role IDs are retained in `agent-contracts.json`; no new swarm is required.

## Authority levels

- **Prepare:** read admitted sources, compare, draft briefs/checklists and record explicit unknowns. No public posting, monetary commitment or rights grant.
- **Shadow:** execute against fixtures or approved private inputs, produce a trace and proposed effect, then compare with a human result.
- **Admitted operation:** a real scoped provider/account grant, funded envelope, verified evidence transport and passing admission tests. Enable per operation, not an unrestricted agent.
- **Public/financial effect:** exact material, channel, audience and budget authorization, where required, followed by an actual receipt. A generated green-light or blank approval field is never sufficient.

Runtime status today: **contract prepared, not deployed**. Schedule and external-write flags are false. A model name in a legacy role is not proof of availability; route by measured task quality/cost in the actual configured runtime.

## Every run

Include run/job ID, tenant/owner, stable artist/release IDs, input source revisions/hashes, requested effect and target, authority grant, cost/time envelope, attempt/idempotency key, outputs with hashes, decision, error category and receipts. Private originals, legal opinions, PII, royalty amounts and credentials stay outside public git.

Lease work and write an append-only step/effect log. Deduplicate provider events and reject stale revisions. Material changes revoke prior approval. Never resend an uncertain external effect before reconciliation. Restore/export must keep stable IDs and lineage when providers change.

## Admission tests

Prove duplicate intake/event has one effect; changed master/artwork invalidates approval; timeout after provider acceptance reconciles; wrong tenant/artist private data is denied; worker crash restores progress; unsubscribe is rechecked before queued delivery; costs stay within budget; statement gaps go to suspense. Test one real provider/account integration before asserting installed automation.

Initial automation: private intake/provenance and read-only hygiene. Then asset packet preparation and projections. Distributor submission remains manual until a supported, authorized adapter is proven. Financial payment and licensing grants are separate mandates.
