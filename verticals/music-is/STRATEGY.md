## 1. The strategic frame

Music IS exists because Frank has 12,000+ Suno songs, scattered Notion pages, no systematic publish pipeline, weak DistroKid discipline, and four label-canons (Frank Riemer, Frank's Vibes, Arcanea, Nona) that need an operating layer.

The operating layer is **not** a Suno wrapper, **not** a DistroKid replacement, **not** a content factory. It is the canon-discipline + persona-multiplication + asset-pipeline + amplification-mesh + royalty-cascade-graph stack that turns Suno output into Arcanea Records as a sustainable label operation.

**First curve:** Frank's operated label — four sub-labels, multiple personas, gated releases, autonomous amplification, sovereign monetization.
**Second curve:** Music IS productized template — sold to other musicians/labels (Phase 5), retains sovereignty clause via SIP attestation.

## 2. Load-bearing decisions (locked — see DECISIONS.md for resolution)

1. **Music IS at `verticals/music-is/`** in this scaffold; long-term home `arcanea-ecosystem/labels/arcanea-records`. Public reference at `verticals/sound-intelligence/` is distinct.
2. **Catalog is truth, dashboard is observability.** Excel + markdown corpus first; `frankx.ai/music/studio/` Next.js dashboard is Phase 4.
3. **Persona is the unit, label is the canonical bucket.** Songs serve personas; personas serve labels; labels serve canon. Persona N+1 spawn refused before persona N hits release-cadence baseline.
4. **`/music-release` non-waivable A&R gate.** No green-light, no streaming, no socials, no NFT, no Bandcamp.
5. **Token tier discipline.** Opus for taste/canon/A&R; Sonnet for prompt synth + composition + orchestration; Haiku for catalog CRUD + tagging + scheduling; external (`/arco`) for Suno/render/Distro/social.
6. **Knowledge core grounded.** `verticals/music-is/knowledge/suno/` distilled corpus from official docs + GitHub wrappers + Reddit + YouTube transcripts.
7. **Engine-agnostic at contract.** Suno today; engine named per catalog row; corpus has per-engine sub-folders.
8. **AI-disclosure structural.** Per persona bio per platform; metadata; attestation per `/sip-attest-audio`.

## 5. Notion architecture — collapse, not extend

User has four live Notion surfaces:
- AI Musicians Hub
- Vibe OS
- FrankX Music Brand Strategy
- Music

The architectural move: **all four become mirror-only.** Single source of truth = local Excel + markdown.

| Notion surface | Role under Music IS | Action |
|---|---|---|
| AI Musicians Hub | Catalog mirror — primary user-facing view | Schema-lock to match `catalog/master.csv`; rename "Music IS — Label Board" |
| Vibe OS | Persona canon library | One row per persona; child page = full canon doc |
| FrankX Music Brand Strategy | Frank Riemer label CANON page only | Migrate to Vibe OS as one row under Frank Riemer label; archive standalone |
| Music | Playlist/release feed for frankx.ai/music | Mirror only — auto-synced from `catalog/released/`; no manual edits |

Notion never authors; Excel + markdown does. Kills "where is the truth?" pain instantly.

## 7. Risk + refusal posture

**Refused at architecture layer:**
- Volume without canon (content-factory drift)
- Persona-multiplication before persona-stability
- Notion-as-source-of-truth drift
- AI-disclosure burial
- Vocal-impersonation without consent on file
- Bot-mesh fan-engagement
- Aggregator master-rights-flip
- Paid-playlist-placement

**Risk-aware operations:**
- Suno API stability — engine-agnostic contract protects against engine-failure or pricing-change
- DistroKid web automation fragility — manual fallback documented per release
- Platform AI-content policy changes — per-platform AI-disclosure compliance audited monthly
- Royalty-graph-on-chain immutability — careful design before mint; cascade splits encoded with Frank as canonical updater (multisig if Phase 6+)
